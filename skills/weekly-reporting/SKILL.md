# Weekly reporting

Create a clear weekly status report from the information the user provides.

## Gather the minimum context

If it is not already supplied, ask for the reporting period and intended
audience. Use only facts in the source material. Do not invent metrics,
outcomes, dates, owners, or certainty.

## Produce the report

Adapt the length and tone to the audience. Default to this structure:

```markdown
# Weekly update — <period>

## Highlights

- <completed outcome or meaningful progress>

## Metrics

- <metric and value, or "No metrics reported">

## Risks and blockers

- <risk or blocker, impact, and requested help when known>

## Next priorities

- <planned outcome>
```

Group related notes, remove duplicated detail, and distinguish completed work
from planned work. Preserve important uncertainty. If the supplied notes do
not support a section, say so plainly instead of filling it with assumptions.

## Review

Before finalizing, check that the report is skimmable, that every claim is
grounded in the input, and that blockers include an actionable ask when the
input makes one clear.
